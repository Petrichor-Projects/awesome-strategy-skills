# Broader Awesome Index Readiness

Do not submit this repository to `sindresorhus/awesome` or a broader Awesome index until every gate below is true.

## Earliest review date

The repository was made public on 2026-08-21. The upstream minimum age is 30 days. Petrichor’s internal legitimacy gate is 90 days, making **2026-11-19** the earliest submission review date.

Age alone is not adoption.

## Independent adoption gates

- [ ] At least three contributors outside Petrichor have an accepted pull request, completed review, or substantive issue that changed the catalog.
- [ ] At least three eligible reviewers have completed the nine-skill benchmark, with material disagreements published.
- [ ] At least five live referring domains point to the repository or companion hub, excluding Petrichor-owned domains, profile links, mirrors, and automated indexes.
- [ ] At least three listed publishers have publicly shared the list, used the optional badge, or linked to their record.
- [ ] The repository has three consecutive monthly maintenance records with stale links, corrections, additions, and removals disclosed.
- [ ] At least one non-positioning fixture is public so the evaluation system is not fitted to Petrichor’s strongest category.

## Upstream compliance gates

The current upstream pull-request template requires a list to be at least 30 days old, use `main`, pass `awesome-lint`, carry `awesome` and `awesome-list` topics, use a Creative Commons license, include contribution guidance, and represent human curation. The submitting person must review four other open pull requests and fully AI-generated pull requests are not accepted.

Before submission:

- [ ] Have Philipp personally re-review every entry and write the submission rationale in his own words.
- [ ] Record that human review without claiming the catalog was produced without AI assistance.
- [ ] Remove the Quality workflow badge from the README. Upstream does not allow CI badges in list READMEs.
- [ ] Make `Contents` the first section and keep its nesting to one level.
- [ ] Resolve GitHub’s `NOASSERTION` license detection even though the root `LICENSE` contains CC0 terms.
- [ ] Recheck the heading and header illustration against the upstream duplicate-title rule.
- [ ] Move any nonessential notices into a `Footnotes` section if the upstream reviewer requests it.
- [ ] Run `npx --yes awesome-lint` from a clean checkout.
- [ ] Confirm no archived, deprecated, undocumented, or unlicensed item remains in the main list.
- [ ] Have Philipp review four other open Awesome pull requests with substantive comments.

## Decision rule

Submit only when every independent-adoption and upstream-compliance gate is checked. Do not buy links, ask for reciprocal approval, or use stars as a substitute for review evidence.

If the repository misses the internal gates on 2026-11-19, publish the maintenance and adoption numbers and extend the window. No exception should be made to hit a calendar date.
